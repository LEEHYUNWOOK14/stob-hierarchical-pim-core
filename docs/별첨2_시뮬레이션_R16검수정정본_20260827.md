**별첨2\_ 시뮬레이션 실험 환경·분기 이력·한계 및 후속 연구**.

• \[분기 명칭\]V·B·L·A·R·C는 서로 다른 가설을 격리하기 위한 내부 실험

서로 다른 판정으로 관리했다. 실행 완료만으로 DRC·timing·power signoff는

**2. 실험을 어떻게 수행했는가**

**2.1 Workload 동결과 입력 재현**

• \[대상 모델\] GR00T 계열 action-head에서 Normalization 호출을
조사하고, 정적 모듈 13개를 확인한 뒤 실제 대표 실행에서 6개
profile·269회 호출을 capture.

• \[범위\] LayerNorm, RMSNorm, AdaLayerNorm-derived pattern을 포함하며,
GR00T 전체 inference가 아니라 action-head 경계의 Normalization
proof-of-concept였다.

• \[대표성\] profile별 1/4/4/128/128/4회 호출 가중치를 유지하여 269-call
cycle·traffic을 계산하고, unique tensor element와 invocation-weighted
element를 분리했다.

**2.2 수치 정확도와 기능 검증**

• \[삼중 기준\] PyTorch BF16 golden, C11 mixed-precision model,
SystemVerilog RTL을 동일 입력으로 실행했다. RTL 대 C11은 bit/element
mismatch 0을 요구하고, PyTorch 대비는 BF16 허용오차와 non-finite 여부를
판정했다.

• \[Protocol stress\] ready/valid stall, backpressure, bank mask, row
tag, context, descriptor, partial/scalar packet,
replay·broadcast·write-back 경로를 self-checking testbench로 검증.

• \[결과\] 6/6 profile PASS, RTL–C11 mismatch 0, 최대 절대오차 0.0156,
NaN/Inf 0, mapping packet 477,312개 round-trip mismatch 0을 확보.

**2.3 아키텍처 비교 실험**

• \[베이스라인 비교 구조\] 일반 메모리+외부 연산(no-PIM SB), Bank-only
PIM+B0 external scalar fallback, 제안 계층구조 PIM을 비교했다.

• \[동일 경계\] Bank-only와 제안 구조는 6 profile·269회 호출, 공통 40
MHz 참조, descriptor·write-back 경계를 맞춰 cycle과 external payload를
비교했다.

• \[Traffic domain\] External, on-die, bank-array movement를 분리하여
제안 구조가 외부 이동을 줄이는 대신 내부 이동이 증가하는 trade-off를
구체적으로 명시했다.

• \[Cycle 경계\] Architecture transaction cycle 963,619→705,247와 lane
microarchitecture DSE 4/8/16-lane cycle은 계측 경계가 달라 별도 표로
유지했다.

**2.4 RTL-to-layout 물리 설계 기법**

• \[기술적 매핑\] Yosys로 Sky130HD 표준셀에 mapping하고
hierarchy·cell/operator count·unmapped primitive를 검사했다.

• \[물리적 구현 단계\] Floorplan/region·bump 조건 고정 → global
placement → detailed legalization → CTS → global route → detailed route
순으로 진행했다.

• \[단일 변수 원칙\] 각 candidate는 placement 위치, layer capacity,
corridor, router iteration 등 하나의 가설만 바꾸고 별도 namespace에서 한
번 실행했다. 자동 retry·fallback·동시 대형 실행을 금지했다.

• \[배선 지표\] unresolved resource, report record, precise/integer
overflow, overflow edge/track, layer별 overflow, wirelength, via,
runtime, RSS를 raw log와 congestion report에서 추출했다.

• \[재개방 검사\] ODB/SDC를 새 OpenROAD 프로세스에서 Liberty-first로
다시 열어 block, clock, bump, region ownership, placement legality,
route 존재 여부를 검사했다.

• \[Power 준비\] Track C는 workload activity(VCD/SAIF 계열)와 Liberty
power를 연결하도록 설계했으나, 최종 post-route 결과는 상세배선·RCX
이후에만 실행하도록 gate를 설정했다.

• \[문제 정의\] 중앙 집중형 구조는 16개 bank의 2048-bit급
global/replay/write-back 경로가 중앙부와 bank 경계를 반복 통과하여,
legal placement 뒤에도 배선 수요가 특정 통로에 집중되는 문제가 있었음.

• \[V2→V4 가설과 해결\] V2의 perimeter HBM pin이 내부 접점을 package
I/O처럼 가장자리에 몰아 인공 병목을 만든다고 가정했다. 565개 command/read
접점을 met5 landing pad로 분산한 V4에서 residual congestion이
1,600,437→2,620으로 99.84% 감소했다. 접점 모델 가설은 지지됐지만 flat
placement 내부 hotspot 2,620은 남았다.

• \[V5 반증\] bank-aware guide가 locality를 높일 것이라 가정했으나, 16개
bank island 사이로 원시 wide bus가 횡단하면서 residual이 1,182,646으로
재악화되었다. 물리적 군집화만으로는 논리적 중앙 의존성을 제거할 수 없다는
반증이 되었다.

• \[WBQ 구조 해결\] 16개 bank를 4개 quad로 묶고
reduction·replay·write-back을 quad-local에서 먼저 처리해 중앙에는 축약된
결과만 전달하도록 RTL 연결 자체를 변경.

**3.3 WBQ B26과 국소 복구 L 계보**

• \[B2–B25 작업 순서\] WBQ 기능 회귀와 Sky130HD mapping 통과 후
floorplan→global placement→resizing→detailed placement→global route
순으로 작업을 진행  
• \[B25 문제\] completion descriptor를 68→17 bit로 줄였는데도 four-quad
exclusive fence 내부에서 detailed placement가 48,736 illegal cell과
17,972 overlap/padding check를 남겼고, 가용 row 부족으로 목표 density가
0.39→0.43으로 상승하는 문제 발생. 핵심 detailed-placement 계산만
10,033초(2:47:13)였으며, 이를 곧 legalization/capacity 실패로 분류했다.

• \[B26 해결 가설\] RTL·mapped netlist·floorplan·SDC·fence를 보존/동결한
상태에서 placement recovery policy만 격리 변경하면 문제를 해결할 수 있을
것으로 가정했다.

• \[L 계보의 결론\] route iteration 증가는 6→89로 악화(L1), global
padding은 4,760,272개 cell을 이동시키고 HPWL을 2% 늘려 route 전 gate에서

**8.4 Local SUM / SUMSQ: Bank-PCU**

**첨부 표 20. Bank-local reduction 수식**

| **식 ID·명칭**           | **수식**                                                                  | **의미·구현**                               |
|--------------------------|---------------------------------------------------------------------------|---------------------------------------------|
| 8-5 · Local SUM          | $sᵣ,ᵦ,ᵥ\  = \ \Sigma\_\{\ell = 0\}\hat{}\{ L - 1\}\ xᵣ,ᵥBL + ᵦL + \ell$   | 한 bank vector의 L=8 lane 합                |
| 8-6 · Local SUMSQ        | $qᵣ,ᵦ,ᵥ\  = \ \Sigma\_\{\ell = 0\}\hat{}\{ L - 1\}\ xᵣ,ᵥBL + ᵦL + \ell ²$ | 같은 vector의 제곱합; x²와 합을 병렬 생성   |
| 8-7 · Bank partial SUM   | $Sᵣ,ᵦ\  = \ \Sigma\_\{ v = 0\}\hat{}\{ V - 1\}\ sᵣ,ᵦ,ᵥ$                   | bank b가 보유한 row 조각의 FP32 부분합      |
| 8-8 · Bank partial SUMSQ | $Qᵣ,ᵦ\  = \ \Sigma\_\{ v = 0\}\hat{}\{ V - 1\}\ qᵣ,ᵦ,ᵥ$                   | bank b가 보유한 row 조각의 FP32 부분 제곱합 |

**첨부 표 21. Local reducer의 실제 진행**

| **순서**    | **데이터/연산**        | **RTL 동작**                                             |
|-------------|------------------------|----------------------------------------------------------|
| 입력        | 8×BF16 activation beat | BF16→FP32 확장 후 x와 x²를 동시에 생성                   |
| lane tree   | 8→4→2→1                | SUM·SUMSQ 각각 pipelined FP32 adder tree                 |
| interleave  | v mod 4 slot           | 연속 vector의 누산 의존성을 4개 slot에 분산              |
| row overlap | local context 2개      | 한 row의 pipeline 잔여 계산 중 다음 row를 ping-pong 보존 |
| 완료        | Sᵣ,ᵦ·Qᵣ,ᵦ·tag          | 모든 vector 완료 후 4 slot을 합쳐 global reducer로 전달  |

**8.5 Global reduction: Logic-die PCU**

**첨부 표 22. 16-bank global reduction 수식**

| **식 ID·명칭**                 | **수식**                                                                                         | **의미·구현**                               |
|--------------------------------|--------------------------------------------------------------------------------------------------|---------------------------------------------|
| 8-9 · Global SUM               | $Sᵣ\  = \ \Sigma\_\{ b = 0\}\hat{}\{ 15\}\ Sᵣ,ᵦ\  = \ \Sigma\_\{ i = 0\}\hat{}\{ N - 1\}\ xᵣ,ᵢ$  | 16개 bank partial SUM을 전역 SUM으로 결합   |
| 8-10 · Global SUMSQ            | $Qᵣ\  = \ \Sigma\_\{ b = 0\}\hat{}\{ 15\}\ Qᵣ,ᵦ\  = \ \Sigma\_\{ i = 0\}\hat{}\{ N - 1\}\ xᵣ,ᵢ²$ | 16개 bank partial SUMSQ를 전역 SUMSQ로 결합 |
| 8-11 · Balanced reduction tree | $S⁽ᵏ⁺¹⁾ⱼ = S⁽ᵏ⁾₂ⱼ + S⁽ᵏ⁾₂ⱼ₊₁;\ \ Q도\ 동일$                                                      | k=0…3의 4-level balanced tree: 16→8→4→2→1   |

• \[배치 이유\] Sᵣ과 Qᵣ는 모든 bank의 부분값을 필요로 하므로 한 bank
내부에서 완결할 수 없었다. bank에서는 원본 N개 대신 bank당 2개의 FP32
scalar만 올리고, cross-bank 결합은 Logic-die에서 수행했다.

• \[동기 조건\] 16개 bank partial과 동일 row tag가 모두 준비된 경우에만
global tree가 시작되며, downstream stall 시 결과·tag를 output register에
유지했다.

**첨부 표 23. LayerNorm과 RMSNorm scalar 수식**

| 8-33 · Write-back traffic | $Bytesᵂᴮᵣ = BVL \cdot 2 = 2N$                          | row당 BF16 write-back: N=2048은 4096 B, N=1536은 3072 B        |

**첨부 표 31. 한 row job의 정확한 처리 순서**

| **순서**           | **발생 조건**             | **수행 위치·작업**                         | **완료 조건/다음 단계**             |
|--------------------|---------------------------|--------------------------------------------|-------------------------------------|
| 1\. Context        | job valid∧ready           | Logic-die: tag·mode·V·1/N·ε·bank mask 저장 | 16-bank full mask와 빈 context      |
| 2\. Reduction read | 16-bank lockstep valid    | Bank-PCU: activation 첫 pass, Sᵣ,ᵦ/Qᵣ,ᵦ    | bank별 V vector 완료                |
| 3\. Global reduce  | 16 partial ready          | Logic-die: Sᵣ/Qᵣ balanced tree             | global scalar pair·tag 생성         |
| 4\. Scalar         | engine request grant      | Logic-die: μ·variance·LUT·NR2              | μ/ρ response와 broadcast            |
| 5\. Replay request | scalar response           | Logic-die→controller: tag·V·bank mask      | request ready까지 유지              |
| 6\. Apply replay   | 16-bank replay lockstep   | Bank-PCU: x/γ/β 둘째 pass, 8-lane apply    | last vector가 output FIFO 진입      |
| 7\. Write-back     | bank별 result valid∧ready | 독립 write path: BF16 y·tag·last 반환      | 모든 bank last 확인 후 context 해제 |

• \[split R/W\] 기본 mode에서 reduction/replay는 하나의 read slot을
공유하지만 write-back은 별도 path이므로, 앞 row의 write-back과 다른
row의 reduction 또는 replay read를 같은 cycle에 진행할 수 있었다.

• \[backpressure\] ready가 0이면 data·tag·last를 그대로 유지하고, FIFO
저장량과 pipeline in-flight 수의 합이 16 미만일 때만 새 apply vector를
받음.

**11. OpenROAD API·TCL 오류로 인한 실험 중단과 코드 수정 이력**

OpenROAD 독립 reopen 검증 과정에서는 처음부터 한 번에 성공한 것이
아니라, Tcl binding·OpenSTA 객체 의미·DRT process-local 상태·SWIG

보존했으며, 오류 원인을 소스·binding·실행 로그로 확인한 뒤 수정된
verifier를 새 실행 경로에 적용했다. 최종 R8에서는 검증기 1회 실행, RCX
1회, 추출 STA/PPA 1회가 모두 완료되었다.

**11.2 핵심 오류의 원인 분석과 해결 가설**

• \[문제 1: C++ API와 Tcl binding의 불일치\] C++ 헤더에 존재하는
iterator 또는 reference-output API가 Tcl에서 동일한 방식으로 호출되었다고
가정한 것이 R1의 원인이었다. 소스의 SWIG \`%ignore\`와 runtime
supported-method를 대조하여 Tcl에서 실제 호출 가능한 메서드만 필수
경로에 남겼다.

• \[문제 2: 객체 이름과 포트 이름의 혼동\] OpenSTA clock 객체 \`clk\`와
SDC source port \`clk_i\`를 동일한 이름으로 취급한 것이 R3의 원인이었다.
이후 검증기는 clock object name, source port name, period, virtual
여부를 별도 필드로 확인했다.

• \[문제 3: 프로세스 문맥 의존 명령\] \`detailed_route_num_drvs\`는
저장된 ODB를 새 프로세스에서 여는 것만으로 재현되는 상태가 아니었다.
따라서 독립 reopen의 필수 성공 조건에서 제거하고 원래 DRT 실행 로그의
source-run 값과 분리했다.

• \[문제 4: 반환형·검증기 구현 오류\] \`getLength\`의 SWIG uint64
pointer와 선언되지 않은 \`api_callable\`은 OpenROAD 설계 데이터의 문제가
아니라 검증 코드의 자료형·변수 범위 문제였다. 반환값을 숫자로 확인하기
전 산술에 사용하지 않고, 로깅 helper의 입력을 명시적으로 전달하도록
수정했다.

• \[해결 가설\] API audit → mock/unit test → 작은 실제 ODB fixture →
frozen canonical R16 reopen 순으로 검증하면, 실행 중 처음 발견되는
오류를 반복하는 대신 필수 API의 binding과 반환형을 사전에 차단할 수
있다. R8 qualification에서 순수 Tcl/mock 64 assertions, main-flow mock,
실제 작은 ODB fixture, Tcl completeness 및 runner fail-closed 검사가
모두 PASS했다.

제거하지 않았으며, 각 실패는 검증기·binding·문맥 문제로 분류했다.

후속 E3/E4/E5/E6 ECO는 2026-08-26~27에 생성된 별도 계보이며, 이 문서의 R16/H16 canonical snapshot(2026-08-25 UTC)을 덮어쓰지 않았다.

**12. 연구윤리·외부 자료·저자 및 AI 기여 고지**

**12.1 연구윤리와 결과 보고의 기본 원칙**

본 연구는 실행 여부, 산출물의 출처(provenance), 물리 설계 및 분석 결과의 판정을 분리하여 기록했다. 실행이 완료되었다는 사실만으로 DRC/LVS, timing closure, power signoff 또는 제조 가능성을 주장하지 않았다. 본문에 보고한 R16/H16 수치는 2026-08-25 UTC 기준 canonical snapshot의 관측값이며, 이후 E3/E4/E5/E6 후속 ECO 결과와 혼합하지 않았다.

실패·중단·미검증 상태는 삭제하거나 성공으로 재분류하지 않고 해당 namespace와 로그에 보존했다. 특히 R11은 사용자 중단으로 `INCONCLUSIVE_USER_STOP`으로 남기고, R8 independent reopen은 `REOPEN_VERIFIED_WITH_LIMITATIONS`로, 선택적 via 독립 재계수와 independent DRT recount은 `NOT_CHECKED`로 표시했다. R16 package provenance는 `PROVENANCE_PARTIAL`, repository-wide provenance는 `PROVENANCE_MISMATCH`로 구분했다.

보고서의 비교 수치와 해석은 실제 동일 조건으로 실행된 범위에 한정했다. R16의 DRT 2,282,092→0, wire 147.956981 m, via 28,032,721개, RCX SPEF 크기, setup/hold WNS 및 vectorless power는 관측 결과로 보고했다. vectorless power를 workload energy로, Sky130HD 연구 구현을 양산 HBM logic-die signoff로, action-head Normalization PoC를 GR00T 전체 inference 가속으로 확대 해석하지 않았다.

**12.2 외부 자료와 소스코드 출처의 구분**

다음 자료와 도구는 연구의 입력·참고·실행 환경으로 사용되었으며, 각각의 원본 결과와 본 연구에서 생성한 결과를 구분했다.

| 자료·도구 | 본 연구에서의 사용 | 제출물에서의 출처·주장 경계 |
|---|---|---|
| Samsung PIMSimulator | PIM 시스템·메모리 모델 관련 참고 또는 기반 코드 계보 | 삼성 원본과 연구자가 작성·수정한 코드를 동일한 것으로 표시하지 않았다. 삼성 PIMSimulator 원본/수정 C++ 코드는 현재 제출물에 포함되지 않았다. |
| DRAMSim2 | HBM2 transaction·memory-service 모델과 baseline traffic | 원본 DRAMSim2와 프로젝트 내 수정·래퍼 코드를 구분했다. `LICENSE-DRAMSIM2` 고지문을 보존했다. |
| MobileNetV4 | 외부 모델·workload 또는 참고 자료 | 본 연구에서 직접 실행한 범위와 공개 모델의 원래 성능·결과를 구분했다. 외부 공개 결과를 본 연구의 측정값처럼 사용하지 않았다. |
| GR00T N1.7 | action-head Normalization 식·호출 경로·pretrained weight 및 6 profile trace의 출처 | 269-call 결과는 전체 GR00T inference가 아니라 pretrained action-head 내부의 synthetic boundary input 기반 Normalization PoC이다. GR00T source와 checkpoint revision을 명시했다. |
| HotSpot·3D-ICE | 열·3D 적층 관련 모델 또는 참고 자료 | 모델의 가정·입력·출력과 본 연구의 결과를 분리했다. 외부 논문·도구의 그림이나 수치를 재현·재사용할 경우 원출처와 수정 여부를 표시했다. |
| OpenROAD·ORFS·Yosys·Sky130HD | 합성·배치·CTS·전역배선·상세배선·RCX/STA 준비 | 도구 버전과 canonical binary를 명시하며, OpenROAD 실행 결과와 foundry signoff를 동일시하지 않았다. |

현재 제출물에 포함되지 않은 것으로 검수된 실행·원본 자료는 다음과 같았다.

- 삼성 PIMSimulator의 원본 및 연구자 수정 C++ 코드
- `sim`, `libdramsim`, `obj_dir` 실행·빌드 산출물
- 외부 논문 PDF/HTML 전체본
- 외부 자료에서 직접 재사용한 그림·표·도식

따라서 보고서와 제출 패키지에는 위 자료를 “제출물에 미포함”으로 명시하고, 제출되지 않은 원본·수정 코드가 포함되어 있다고 암시하지 않았다. 연구자가 직접 작성하거나 수정한 코드가 별도 제출되는 경우에는 원본 프로젝트명, 원본 저장소·버전 또는 commit, 수정 범위, 연구자 작성 파일 및 파일 경로를 각각 명시했다. 현재 확보된 보고서 정보만으로 원본 코드의 정확한 commit이나 재배포 허가를 확인할 수 없다면 해당 값을 추정해 기재하지 않았다. 라이선스 조건이나 재배포 허가를 확인하지 못한 경우에는 허가가 있다고 추정하지 않으며, 해당 코드의 재배포·공개 여부는 라이선스와 대회 제출 규정 확인 후 결정했다.

**12.3 저작권·라이선스 및 그림 재사용 고지**

외부 코드·모델·논문·제조사 자료를 사용할 때에는 저작권과 라이선스 조건을 연구윤리의 일부로 관리했다. 본 제출물은 출처를 적었다는 이유만으로 외부 코드의 재배포 권한이 생긴다고 보지 않았다. 따라서 다음 고지문을 제출 패키지의 라이선스/고지 파일에도 유지했다.

논문이나 제조사 자료의 그림을 직접 재사용한 경우에는 그림 캡션에 원출처를 명시하고, 다음 중 해당 상태를 표시했다: `원본 재사용`, `일부 수정(adapted)`, `연구자 재작성(redrawn)`. 원본 그림을 연구자 결과처럼 제시하지 않았으며, 라이선스상 재사용이 불확실한 그림은 직접 재작성하거나 제출물에서 제외했다.

**12.4 연구자와 AI 도구의 기여 구분**

최종 연구 질문, 계층형 PIM 구조와 WBQ 전환 결정, 실험 설계, 증거 해석, 한계 설정, 결과 주장 및 제출 승인은 인간 연구자가 담당했다. AI 도구가 사용된 경우 그 역할은 코드 초안, 로그 파싱 보조, 실험 장부 정리, 문서 형식화 등 보조적 작업으로 한정하여 기록했다. AI가 실행하지 않은 실험이나 확인하지 않은 결과를 수행한 것처럼 표시하지 않았다.

제출 규정이 허용하는 경우 다음 고지를 사용했다.

> AI-assisted tools were used for code drafting, log parsing, experiment bookkeeping, and document formatting. Final research questions, architecture decisions, interpretation of results, limitations, and submission claims were reviewed and approved by the human project author.

한국어 고지는 다음과 같이 기재했다.

> 본 연구에서는 코드 초안 작성, 로그 파싱, 실험 장부 정리 및 문서 형식화를 위해 AI 보조 도구를 사용하였다. 최종 연구 질문, 아키텍처 결정, 결과 해석, 한계 설정 및 제출물의 주장은 인간 프로젝트 저자가 검토하고 승인하였다.

이 고지는 실제 사용 범위와 제출 규정에 맞게 조정했다. AI가 생성한 초안은 출처·수치·라이선스·주장 범위를 인간 연구자가 확인한 후에만 제출물에 반영했고, AI를 저자 또는 실험 수행자로 허위 표시하지 않았다.
